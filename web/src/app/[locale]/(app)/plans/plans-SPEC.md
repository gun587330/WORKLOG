> 이 화면의 단일 명세서. 최종 수정: 2026-10-21 · 상태: **1차 구현 완료(백엔드 연결 전)**

## 1. 목적

**목표(G<n>)** 를 만들고, 한 기간의 **계획(PL-…)** 을 md 로 올려 목표별 **할 일(G<n>-<m>)** 을 쌓는다. 할 일은 기록 md 의 `## 목표 진행` 이 완료로 바꾼다.
머리 우측 [이번 주 컨텍스트 복사] 는 `context_pack` 텍스트(프로젝트 · 진행 중 목표 · 진행 중 계획의 할 일 · 최근 기록 · 미완 할 일, 끝줄 "이 목록에 없는 코드는 존재하지 않는다")를 클립보드로 보낸다. 모든 프롬프트가 이 글을 먼저 받는다.

## 2. 레이아웃 (세로 100%, 좌우 1:1)

- **좌 · 계획**: [계획 · md 로 올려요 · N건 | 새 계획 올리기(블랙 sm)] · 카드 목록(최근 기간순): 기간 · 코드(모노) · 제목 · 프로젝트 칩 + 상태 칩(진행 중 caution / 완료 pass) | 우측 큰 숫자 = 목표 수, 아래 「목표 · 할 일 N · 완료 M」. 누르면 **상세 모달**. 푸터 2줄.
- **상세 모달**(lg): 제목 + 코드 · 기간 · 요약 · 목표별 묶음(코드 칩 · 제목 · 프로젝트 칩) 아래 할 일 행(네모 체크 = `set_plan_item_status` · 코드 · 제목 · 완료 보고 기록 링크 · 기한) · 「원문 md 보기」 접힘 · 푸터 [계획 삭제(danger sm)] [닫기]. 삭제 = 확인 모달(할 일도 지워지고 [신규] 로 만든 목표는 남는다).
- **우 · 목표**: [목표 · N개 · 진행 중 M | 필터 칩(진행 중 · 완료 · 전체) | 목표 추가(블랙 sm)] · 평면 행 목록: 코드 칩 · 제목 + **프로젝트 배지** + (보류/완료 칩) · 기간 · 할 일 수 | % · N/M | 수정 · 삭제 아이콘. 진행 중이 아닌 행은 흐림. 푸터 2줄.
- **목표 폼 모달**(lg): 제목 · 프로젝트(칩 선택) · 시작 · 끝(date) · 상태(수정 때만, 세그먼트) · 메모 → [저장] = `upsert_goal`(새 목표는 코드 자동 발급). 삭제 = 확인 모달, 계획 항목이 달린 목표는 서버가 거절하므로 버튼을 비활성화하고 상태 변경을 안내.
- `?plan=<id>` 로 들어오면 그 계획의 상세 모달을 바로 열고 주소에서 지운다(홈의 [열기]).

## 3. 계획 올리기 모달

①입력(파일 · 붙여넣기) ②검수: 제목 + 코드(기간에서 계산: 7일 이하 = `PL-YYYY-Www`, 아니면 `PL-YYYY-MM`) · 기간 · 요약 · 목표 N · 할 일 N · 판단 필요 N · **목표별 줄**(기존 코드는 서버의 제목으로 확인, `[신규]` 는 신규 칩 + 프로젝트 코드) · 기한 날짜 요약 · 문제 · 참고(「[신규] 목표 N개를 새로 만들어요」 · 비슷한 제목의 기존 목표 경고) → [게시] = `insert_plan` 한 트랜잭션(목표 생성 · 할 일 순번은 목표별 최대값 다음) + `insert_links`.
게시를 막는 문제: 머리말 · period · title · kind 불일치 · 목표/할 일 비어 있음 · 목표 코드 없음 · [신규] 프로젝트 코드 없음/미등록 · 할 일의 참조 불명 · 같은 코드의 계획 존재.

## 4. 파서 규칙 (`lib/work-plan.ts`)

머리말 `kind: plan` · `period: YYYY-MM-DD ~ YYYY-MM-DD` · `title` · `author` · `summary`. `## 목표` = `- G12 제목` 또는 `- [신규] 제목 (P-코드)`(임시 참조 N1, N2…). `## 할 일` = `- [ ] G12 제목 (MM-DD)` 또는 `- [ ] [신규]제목(띄어쓰기 없이) 제목 (MM-DD)`. `## 판단 필요` · `## 기록 출처`. 본문 `[[코드]]` → links.

## 5. 결정 로그

- 2026-10-21 목표는 프로젝트별 묶음이 아니라 **평면 목록**에 프로젝트 배지(가안 v11). 묶음 접기는 쓰지 않는다.
- 2026-10-21 계획 상세는 별도 라우트가 아니라 모달. 계획 삭제는 상세 모달 안에서만.
- 2026-10-21 목표 폼의 프로젝트는 셀렉트가 아니라 칩 선택(공용 컴포넌트만 쓰는 규칙, 셀렉트 컴포넌트를 새로 만들지 않음).
