## 1. 목적

하루 작업을 **자기 AI 로 정리해 md 로 올리고** 타임라인으로 다시 본다. 흐름은 셋.
1. 프롬프트 박스에서 「작업 기록용 프롬프트」를 [복사] → AI 에 붙여넣기. 프롬프트는 먼저 **컨텍스트 팩**(계획 화면 [이번 주 컨텍스트 복사])을 요구하고 그 안의 코드(P- · G · G-n)만 쓴다.
2. AI 가 질문 뒤 `작업기록_날짜_이름.md` 를 내려준다(코드블록 폴백).
3. [새 기록 올리기] → 파일/붙여넣기 → 검수(파서 문제 + 코드 대조) → [게시] → 상세.

양식의 단일 원본은 `supabase/seed/prompts/work-log.md`(= `prompts` 시드)이고 파서 `lib/work-log.ts` 는 그 양식만 안다. 양식을 바꾸면 같은 작업에서 시드 → 새 마이그레이션 → 파서 → VOCAB → 이 문서를 고친다.

## 2. 목록 레이아웃 (세로 100%)

- **머리**: 「작업 기록」 + 우측 **프로젝트 필터 칩**(전체 N · 프로젝트별 건수, 등록된 기록의 프로젝트에서 자동).
- **프롬프트 박스**(높이 고정): [프롬프트 N개 | 프롬프트 추가(블랙 sm)] · 회색 면 카드(제목 · 용도 · 수정일 · [복사] [전체 보기]) 가로 드래그 · 끝에 점선 [프롬프트 추가] · 푸터 안내. 전체 보기 = 읽기 전용 폼 모달(용도 · 본문 · [프롬프트 복사]). 추가 = 폼 모달(제목 · 용도 · 본문).
- **기록 박스**(나머지 높이): [기록 N건 · 최근순 | 새 기록 올리기(블랙 sm)] · **한 줄 가로 카드**(열 폭 `clamp(18rem, 26vw, 24rem)`, 드래그 · 세로 휠을 가로로, 끌었으면 클릭 삼킴) · 푸터(좌우로 끌어서 넘겨요 · 카드를 누르면 상세).
- **기록 카드**: 회색 면(`--bg-soft`) · 테두리 없음 · 호버 = 틴트 + 음영 + 2px 들림. 날짜(요일) + 코드(L-…) · 요약(6줄 말줄임) · 프로젝트 칩(하단) · 작업 / 완료 / 실제 투입 · 호버 시 우상단 삭제 아이콘(danger 원본, 확인 모달 → `delete_work_log`, 이 기록이 완료 처리한 계획 항목은 미완으로).
- **올리기 모달**(lg): ①입력 = 세그먼트[파일 올리기 | 붙여넣기] ②검수 = 날짜 · 실명 · 요약 · 작업/완료/투입/할 일/프로젝트 + 문제 목록 + 「목표 진행」 완료 코드 안내 → [게시]. 게시를 막는 문제: 머리말 · date · author · 작업 섹션 없음 · kind 불일치 · 프로젝트 코드 없음/모양 틀림/미등록 · 목표 코드 모양 틀림/없음. 서버 거절(예: 계획 항목 코드 없음)은 사유를 그대로 띄운다. 올릴 때마다 새 행.

## 3. 상세 레이아웃 (`/logs/[id]`)

좌 20rem · 우 20rem 고정, 중앙 = 나머지. 머리 = 꺾쇠(작업 기록으로) + 코드.
- **좌**(sticky): 목차(시각 · 제목, 현재 위치, 누르면 카드 펼침) · **프로젝트** 칩(건수, 필터) · 태그 칩(빈도순, 필터).
- **중앙**: 날짜(요일) · 작성자 · 코드 → 오늘 요약 → 「작업 타임라인」 + [모두 펼치기/접기] → 카드(`details`, **기본 접힘**: 시각 · 제목 · 프로젝트 칩 · 목표 코드 · 상태 칩). 펼치면 태그 · 본문(표 · 인용 · `::: 토글`). 레일 + 둥근 삼각형 마커(완료 = 블랙, 진행 중 = 주의색).
- **우**(sticky): 한 줄 통계 4칸 → 시간대별 작업량(숫자 · 24시간 면 스파크라인 · 호버 · 축 · 구간) → **목표 진행**(완료 코드 = 채운 네모 + 항목 제목, 손댄 코드 = 빈 네모) → 앞으로 할 일(판단 필요 강조 · 계획 항목 코드 칩).

## 5. 파서 규칙 (`lib/work-log.ts`) — anserx 와 다른 점

- 머리말 `kind: log` · `date · author · role · summary`. `kind` 가 plan 이면 문제(계획 올리기로 안내).
- 작업 메타 `프로젝트: P-<SLUG>`(필수) · `목표: G<n>`(선택) · `태그:` · `상태:`. 구 `카테고리:` 줄은 프로젝트 줄로 읽되 값은 P-코드여야 한다.
- 새 섹션 `## 목표 진행`: `- [x] G12-3` = 완료(`completions`), `- [ ] G12-4` = 손댐(`touched`). 모양이 G-n-m 이 아니면 문제.
- `## 앞으로 할 일` 줄이 `G12-3 제목` 으로 시작하면 `planItemCode` 로 연결. `판단 필요:` 접두 = `needsDecision`.
- 본문 `[[P-ANSERX]]` `[[G12]]` `[[G12-3]]` `[[PL-2026-W43]]` `[[L-2026-10-19]]` → `links`(wikilink). 메타의 프로젝트 · 목표 · 완료 코드 → `links`(ref).
- 정규화 · 토글 · 시간표(24행 · 0.25 단위) 는 anserx 와 같다.
